Definitions

Fusion mode
IMU: accelerometer + gyroscope. NDOF: the same plus the magnetometer, which holds the heading steady in a clean magnetic field.
Gesture frame
Fixed: the sensor axes named in tuning.toml [orientation]. World (--gravity): up from gravity, right from the startup shuffle.
Calibration
The sensor's own rating of each part, 0 (none) to 3 (full). sys is the overall rating and is meaningful in NDOF mode.
Near miss
A movement that reached 50% of the threshold but did not fire: below the threshold, or blocked by the rest or cooldown delay.
Rise time
From the axis leaving rest to the threshold being crossed: the delay the threshold itself adds.
Tilt error
A still sensor should read zero acceleration once gravity is removed. What is left over shows how far the sensor's idea of 'up' has tilted.
Heading drift
How far the orientation turned about the vertical while the sensor was still. Hand tremor counts too; the cleanest reading is with the controller on a table.
Magnetic field
Strength at the sensor, NDOF mode only. Earth's field is 25 to 65 microtesla; much more means a magnet, speaker or battery bank nearby.
Input latency, median
Sensor read to key sent, for a typical sample.
Input latency, p95
19 in 20 samples are faster than this.
Input latency, p99
99 in 100 samples are faster than this.
Input latency, worst
The slowest sample of the session.
Gesture latency, median
The same measure, only for samples that fired a gesture.
Jitter
Standard deviation of input latency: how uneven the controller feels.
Host share, median
Arrival at the PC to key sent. The rest is the link.
Sample loss
Samples the controller sent that never arrived.
Longest gap
Longest stretch with no sample: the worst freeze.
Sample rate
How often the controller actually reads the sensor.
Clock drift
ESP32 clock speed against the PC clock (+ = fast). Corrected for.
Interruptions
Times the link dropped and came back.
